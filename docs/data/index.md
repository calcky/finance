# 数据与更新

当前仓库尚未收录真实金融时间序列，也没有启用自动抓取或定时任务。本节约定后续数据的保存和更新方式，基础文档中的假设数字不会进入真实数据集。

## 保存位置

小型、允许公开再分发的数据集保存在仓库根目录 `data/`，采用 UTF-8 CSV。数据说明和分析放在文档中；构建出的 HTML 不入库。

每个数据集使用一个 CSV 和一份同名说明，例如 `data/money-supply.csv` 与 `data/money-supply.md`。这是命名示例，并非已经提供的数据文件。说明包含序列定义、单位、频率、口径变化、缺失值约定和更新记录。

大型原始文件或不允许再分发的数据只记录来源与获取办法。公开网页上的数据不自动等于可以镜像发布的数据。

## 每条观测至少记录

| 字段 | 含义 | 约定 |
|---|---|---|
| `series_id` | 指标序列标识 | 英文稳定名称，不混合不同口径 |
| `period` | 统计期间或报价时点 | 月度 `YYYY-MM`、季度 `YYYY-Qn`、日度 `YYYY-MM-DD`；日内报价另含时间与时区 |
| `value` | 数值 | 纯数字；缺失留空，不能用 0 代替 |
| `unit` | 单位 | 同一序列保持一致，例如 `CNY_100m`、`percent` |
| `published_at` | 来源发布时间 | 已知日期或带时区时间；未知留空，不用抓取时间冒充 |
| `retrieved_at` | 获取时间 | 带时区的 ISO 8601 时间 |
| `source_url` | 对应发布页或数据文件 | 尽量指向具体发布物，而非机构首页 |
| `note` | 口径、修订或异常说明 | 可为空；需要解释的变化必须写明 |

一份 CSV 默认保存每个 `series_id + period` 的最新可得版本，组合键不得重复。Git 提交记录和数据集说明保留修订过程；如果研究需要同时比较初值与修订值，应明确增加版本维度，不能悄悄混入重复行。

## 一次更新的流程

1. 确认来源已发布新数据，核对使用与再分发条件。
2. 核对统计期间、单位、季调、同比 / 环比和新旧口径。
3. 更新 CSV，补齐发布时间、获取时间与具体来源。
4. 检查重复键、缺失值、异常变化，以及来源是否修订了历史值。
5. 在同名说明中记录新增期间、修订范围和原因；涉及口径变化时同步修订指标说明。
6. 构建文档并检查链接，审核变更后提交与推送。

数据未发布、来源暂时不可用或校验失败时，保留上一次有效数据并明确说明缺口，不用估计值填成官方值。

## 更新频率如何确定

月度宏观指标在正式发布后更新，GDP 跟随季度及修订发布，政策利率跟随政策公告，行情跟随选定产品的采样频率。网站构建时间与数据更新时间不同，页面变新不意味着所有指标都变新。

以后接入自动采集时，采集任务负责下载、校验和记录；Read the Docs 负责把已经审核并入库的内容构建为网站。构建文档本身不依赖实时行情接口，以便离线复现，也避免来源故障导致知识文档无法发布。
